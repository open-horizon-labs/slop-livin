# slop-livin — founding session

## Aim
Developers running many coding agents keep enough free space to keep working, without emergency scans and repeated cleanup. Desired behavior: know what grew, by project, and what to do about it — where "do" is one of four verbs (delete, archive, prevent, leave), chosen ahead of an incident, and where the everyday operator is an AI agent acting on the developer's behalf with the developer authorizing anything destructive.

## Problem Space (carried from the Mole session, 2026-09-17)
- Unit of decision is the **project**, with **activity** as the deciding attribute. Per-artifact-type buckets were unanswerable; every answer was "depends whether the project is active."
- Four response verbs, not one: delete (build output of inactive projects), archive (whole inactive project), prevent (151 `node_modules` → "use pnpm"), leave (`.git`, always).
- Three grouping axes: artifact type × project × worktree (worktree nests in project; type cuts across).
- Docker is a separate accounting domain: ~24 GB inside a VM disk, invisible to any walk; attribution via labels (rare) or name heuristics; shared-vs-unique layers mean reclaim is set-valued.
- Volume truth: 360 GB used, index covers 200 GB, ~47 GB unattributed after all top-level dirs; 3 APFS local snapshots present → "bytes deleted" ≠ "space freed".
- Measured on one machine, one operator, one day, no disk pressure during observation (100 GB free). n=1; the zero-deletion signal is weak.

## Salvage (carried)
Plumbing that carries over from `muness/mole` branch `integrate`: parallel walk with folding and deterministic hardlink attribution; one-base + reverse-delta log (zstd-9/3); FSEvents cgo helper (flat ~0.13 s replay, ~16 h horizon); opt-in LaunchAgent refresh; device boundary; abandon-not-join for stalled reads; three AST audits. Known defects on import: store keyed per root (8 overlapping stores); `RepoRootID`/`LinkedWorktree` declared but never populated; TUI deletion doesn't invalidate; per-keypress rescan. The Mole surfaces (tree TUI, growth view) do not carry over.

Architecture reference: `~/src/open-horizon-labs/repo-native-alignment` — `Extractor` per source, `Enricher` async, event bus with consumers, provenance + confidence on every fact; guardrails `extract-fully-at-parse-time`, `computed-but-not-delivered`.

Competitive gap (researched 2026-09-17): kondo has the project model (marker files, `--older`) but is stateless, `rm -rf`, no Docker/worktrees. StorageRadar has the only growth history (manual directory snapshots, GUI, $19.99) and a read-only MCP endpoint for agents. Nothing combines project model × persistent history × Docker × worktrees × agent operation.

## Hard constraints
- Deletion always routes through protection / whitelist / dry-run / action-boundary checks with a live recheck at the sink. Index is evidence, never authorization. **An agent is also never authorization.**
- Git worktree staleness is not decidable → never a "safe to delete" verdict for a worktree; activity is a signal.
- Folded artifact trees are one unit of action each.
- Totals must match a live walk of what was scanned; coverage vs volume reported separately and honestly.
- Trash by default for user-facing removals.
- Rust. Single static binary; FSEvents via CoreServices FFI in-process (no separate helper). Decided 2026-09-18: fspulse scanner and reverse-delta design were Rust; repo-native-alignment (the architecture reference) is Rust; arrow-rs/parquet tooling is stronger. The Go plumbing on mole `integrate` is a *design* reference and test oracle, not a port source.
- No claiming a trial passed before it is observed.

## Problem Weave

**Current frame:** A developer running many coding agents wants free space to stay workable without emergency scans. The everyday operator is an agent; the human only authorizes. Four verbs (delete / archive / prevent / leave) applied to projects, with activity deciding.
**Layers used:** Agent as operator (A) — what the agent must be able to ask, propose, and be refused. Safety & human authorization (H) — what is structurally impossible and what consent looks like. Domain model & system (D) — what must be representable so decisions attach to durable things. Evidence & measurement (E) — how anyone would know the loop works and is safe.
**Independence:** four parallel agents, same contract, no cross-reading.
**Status:** candidate frames; one material opposition (recommendation vs verdict) needs the maintainer's call; the rest are sequencing or evidence.
**Inputs:** `## Aim`, `## Problem Space`, `## Salvage`, `## Hard constraints` above.

### Shared Core (every layer landed here independently)
1. **Decisions attach to entities, not paths.** Project identity from git's object store (survives rename/move/archive); artifact instance keyed by (project, kind, relative location) so delete-then-rebuild is *regrowth of one thing*. Path is an attribute. (D-2, D-4; A-4 and H-1 both depend on it.)
2. **Every fact carries source, confidence, and freshness.** Not advisory — a bare number is a defect because the agent will sum a walked byte with an inferred Docker byte and act on a 16-hour-old fact. (A-1, D-5, D-7, E-5, H-3)
3. **Proposer can never be authorizer.** The agent produces a frozen plan; execution accepts only a plan reference plus a *grant* the agent could not have minted. Grant = verb + predicate over tool-computed facts + scope + expiry + blast-radius budget. Re-derived at the sink from fresh facts; "could not re-observe" is a refusal. (A-3, A-4, H-1, H-2, H-5)
4. **Success = free space observed after, not bytes deleted.** Trash, APFS snapshots, and concurrent writers make the gap the normal case. The model holds three terms: attributed, volume-reported, named residual. (A-6, D-6, E-4)
5. **The ledger is not the index.** The index is a rebuildable cache; the ledger (verb, entity, evidence, grant, actor, observed effect) must outlive it. (D-10, H-7, E-4)
6. **Stopping is a success state with a named cause.** nothing-worth-doing / insufficient-evidence / index-stale / busy / claimed-by-another-agent / awaiting-authorization. An agent that can't tell them apart retries forever. (A-5, A-8, H-6)
7. **Absence is caught statically.** The two costliest prior defects (unpopulated identity columns, deletion never invalidating) were invisible to green tests. Extend source-invariant audits: every declared column has a writer, every identity produced is consumed, no sink reads identity from the index without live rebinding. (D-11)

### Distinct Problem Statements (kept separate on purpose)
1. **Agent:** an agent needs question-shaped answers with a recommended verb and a way to stop, because it has speed and no peripheral vision; today every surface is a size tree for a human.
2. **Safety:** a developer needs a consent object between "confirm each" and "let it clean," because per-action confirmation trains rubber-stamping and standing trust is a blank check; today no such object exists.
3. **Model:** the four verbs need a stable subject that survives rename, rebuild, and medium (Docker has no path), because path-keyed decisions get re-asked exactly when they matter.
4. **Evidence:** nobody can yet say whether the loop works; every number is instrument telemetry from one machine-day and the premise (pressure ever occurs; the agent raises decision throughput) is untested.

### Opposition and Uncertainty
- **Recommended verb (A-2) vs no verdict register (H-3).** Type: true trade-off. Resolution candidate from D-9: the tool never says "safe"; it says *kind = build output, recovery = local rebuild, activity signals = {…}, matches grant G3*. The verb is a consequence of the human's grant plus the kind's recovery contract, not the tool's opinion. Decision: maintainer. Test: give an agent the fact-only output and see whether it plans soundly.
- **Archive above delete (H-4).** Type: evidence dispute. Decide by observing a real mid-flight ENOSPC on a multi-GB archive.
- **Trash-by-default vs freeing space.** Type: trade-off nobody named before. Deleting 8 GB to Trash frees nothing until emptied; snapshots may pin it after. If Trash is bypassed, that is a distinct verb with its own bar, not a flag.
- **GB-shaped outcome biases toward `delete`** (E). Type: evidence design creating safety pressure. `archive` and `prevent` never register on free space the day they're chosen. Needs a second outcome (re-ask rate, regrowth count) or they'll be starved.
- **Sink recheck cost (H-5) vs batch speed (E).** Type: evidence dispute. Measure proposal-to-execution window and divergence rate under real churn first.
- **Docker: extractor now (D-7/D-8) vs fact-only until a sink recheck exists (H).** Type: sequencing. Both hold: extract and attribute now, no destructive Docker verb until the daemon-side recheck is statable.

### Missing branches surfaced (nobody owned these before)
- The **generator** of an artifact (pnpm/npm, cargo, xcodebuild) has no entity; `prevent` therefore has no subject to record in the ledger.
- **Snapshots** may deserve to be entities with their own extractor, not a cause-of-residual.
- **Attribute the 47 GB once** — a one-command question with no recorded answer; every coverage claim is unsound until it has one.
- **Confidence decay** — a stale high-confidence signal is worse than a fresh low one.
- **Entity merge/split** once repo detection unifies path-keyed projects.
- **Silence on an authorization request** — neither approval nor refusal.
- **Tool-side circuit breaker** for a misbehaving agent (proposal rate, retries against refused units).
- **Agent reads its own history** — "this regrew 4× → propose prevent, not delete."
- **Regret rate** from Trash restores; **near-misses** caught at the sink — free safety signals currently discarded.

### Recommended Working Frame
Build an *entity graph with a consent ledger*, operated through a question-shaped agent surface, where the tool supplies facts with provenance and the human supplies grants; a verb is the intersection. Verify in free-space terms. Measure as an instrumented case study, not a trial.

### Alternate Frames Worth Keeping
- **Ranked list + `--json` is enough** (skeptic): if agents rank raw inventory themselves regardless, the MCP/question surface is overbuilt. A-2's review trigger decides.
- **Cube not graph**: artifact × project × worktree with cheap arithmetic; loses only if Docker's weak join or D-9's restore-source can't collapse to attributes.

### Evidence and Invalidation
- Need to learn: does pressure ever occur on the target machine; what the 47 GB is; divergence rate proposal→sink under churn; whether fact-only output yields sound agent plans; ledger growth over a month.
- Signal this synthesis is wrong: a month with zero floor crossings (premise gone); developers write one broad grant on day one (grant became the blank check); path-keyed view never re-asks after a rename (entity layer is overhead).
